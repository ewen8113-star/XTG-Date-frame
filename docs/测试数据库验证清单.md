# 测试数据库验证清单

执行 `npm run db:seed-test` 会清空业务数据并重新生成以下固定测试数据。系统登录账户不受影响。

## 数据规模

- 经纪人：6 名
- 通告：29 条
- 签约者：6 名
- 引荐关系：3 条
- 导入批次：1 个（全流程测试数据库）

## 身份与奖励

| 测试对象 | 状态 | 重点验证 |
| --- | --- | --- |
| 测试-小肉 | 第一期初始种子 | 自身通告奖励；下线小明、小华的上线收益 |
| 测试-小明待晋升 | 普通经纪人 + 种子1 | 计划开始后的通告计算本人奖励并累计 6+2；通告同时计入小肉上线收益；尚未开放引荐 |
| 测试-小华已晋升 | 种子经纪人｜种子1 | 计划开始后的晋升前后通告均计算本人奖励；对小肉的上线收益继续保留；已开放引荐 |
| 测试-小周二级下线 | 普通经纪人 + 种子1 | 继承小华的种子1归属并计算本人奖励；直接上线小华获得对应收益 |
| 测试-第二期种子 | 第二期种子 | 第二期身份、正常奖励和举报取消 |
| 测试-无身份经纪人 | 无种子身份 | 通告不进入种子奖励审核与结算 |

## 签约去重

在“测试-小华已晋升”中按时间查看：

1. `测试-小华晋升前01` 的签约者为“测试模特-初夏”。
2. `测试-小华晋升后新签` 再次签约“测试模特-初夏”，应与计划生效后的晋升前记录去重并判定为历史重复。
3. `测试-小华晋升后重复` 再次签约“测试模特-初夏”，同样判定为历史重复。
4. `测试-小华晋升后第二新签` 的“测试模特-沐晴”应判定为新增签约。

## 审核异常

- `测试-小华凭证异议`：有测试视频凭证，审核说明带“凭证异议”。
- `测试-二级下线资料不符`：新增签约不通过，原因是资料与本人不符。
- `测试-小明来源取消`：系统自动取消，无有效签约。
- `测试-第二期举报取消`：举报成立后取消。
- 多条待审核通告：用于测试人工审核、保存和状态刷新。

## 周期归属

- 每条已结束通告的结束节点为工作日期加工作时段结束时间。
- 小华晋升前的 6 条通告分布在 6 月和 7 月，只要晚于计划身份生效时间，均进入对应周期并计算本人奖励。
- 进行中通告保留在当前数据中，不应被错误归入已结束周期。

## 签约者资料页

从通告详情的签约者卡片或经纪人工作台“已签约名单”点击签约者姓名进入详情页。重点检查：

- 头像、账号状态、联系方式、注册与登录信息。
- 身高、体重、三围、肩宽、鞋码、服装码、纹身和语言。
- 个人简介、模卡图片、视频资料。
- 已签约通告历史与对应经纪人。

## 财务流程

测试库不预生成付款单。先完成通告审核并生成结算，再依次验证提交付款、财务审批、付款完成和已付款归档；旧浏览器付款单状态会在加载新版页面时清除。
